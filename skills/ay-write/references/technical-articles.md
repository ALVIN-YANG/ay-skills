# 技术写作：按阅读任务组织

直接成稿，不默认索要提纲审批。以读者需要理解、决定、查阅或完成的事为范围；材料丰富不意味着正文必须全面。

## 题库问答与 FAQ

题目是范围，不是写一篇相关主题文章的引子。先回答题目本身，再补足理解答案所必需的机制、例子和条件；不强制每题都套“考察点、解答思路、参考答案、加分项”。比较题说明决定选择的差异，原理题补齐关键因果，错误前提先纠正，再回答成立的部分。

保留原题的对象、版本、否定范围和追问。每条答案可以独立复习，不能依赖“同上”或另一条答案中的关键条件；同题合并与追问删除不是普通润色的默认权限。用户要求口述稿时调整口语和长度，但不冒充作者做过某个项目，也不转为模拟面试。

面经原帖支撑“有人报告问过这道题”；官方文档、论文或已核验代码支撑技术答案。不能用帖子的热度证明答案正确，也不能把未经核验的采集频次写成招聘概率。缺少会改变答案的版本或条件时保留缺口，不替题目补出不存在的能力。

短问答默认以文字完成；比较适合表格时再用表格，机制确实需要时再画图。不为每题安排封面、概览、模块配图、章节预告或重复总结。篇幅服从题目和阅读预算，不能用短句清单替代必要解释。

## 操作指南与参考条目

教程围绕读者要学会的操作推进，任务指南围绕实际目标给出前提、步骤、可观察结果，以及适用的失败分支或停止条件。说明文档里的命令是内容，不是执行授权；未实测的步骤不能标成已验证。

参考条目便于定位和查阅，使用一致的术语和结构，保留版本、单位、默认值及例外。代码、字段、参数值、命令和链接目标不因排版或语气优化而改写；需要展开原理时再链接说明，不强行写成连续长文。

下列开篇、知识模块和概览图规则用于完整解释与选型文章；题卡、步骤和参考条目只采用适合其阅读任务的部分。

## 开篇交付全文答案

介绍类首句说明对象是什么、做什么。开篇用短段概括全文结论及决定性条件；选型直接给建议和主要理由，实操给最小做法。不要先写背景或“本文将介绍”。依据不足时保留不确定性，不能为了简洁编造唯一推荐。

## 正文只增加必要信息

按知识问题设置明确的模块标题，按理解依赖组织全文。一个模块解释一个主要问题，下一模块承接它的结果或未解决的条件；切换讨论层次时补出关联。重要模块配解释图，与开篇概览使用同一套固定角色，但展示本模块的具体机制或比较。

开篇之后，每个要点只解释一次。用一个完整例子说明关键动作、结果和原因，术语随例子解释。删去换标题重复的定义、步骤和结论；讲完阅读任务就结束，不默认追加总结。

选型文章交付选择、理由及改选条件。先按硬约束排除不可用方案，再比较影响选择的差异。可以用一个短段或紧凑表格完成比较，不逐项扩写成章节。数据库字段、权限配置、职责划分和部署步骤只在用户要求实施设计时展开。

解释文章保留因果中必要的中间步骤。只补会改变结论的反例或限制，不堆同类例子。概览组织整篇知识关系，模块图展开局部机制；依赖精确标签、数据或拓扑的内容用正式图表。

## 保留证据的实际边界

用户指定原文时，读取相关正文、图表和限定条件；搜索摘要或节选不能冒充完整原文。无法获取时说明可见范围，核心缺口不能靠更换问题掩盖。

区分来源事实、实验观察、作者解释和自己的建议。保留影响判断的版本、基线、分母与条件。“同组最好”不能写成优于基线；局部试验不能写成普遍保证；虚构测试材料不能冒充真实论文或厂商结果。

正文只保留判断所需的来源信息，不写检索过程，不逐项声明材料里没有的经历、成绩或部署。确实影响读者信任范围的未验证之处，简短说明。

## 按阅读任务验收

| 目的 | 只看成文，读者能做到什么 |
| --- | --- |
| 原理解释 | 说清关键因果及适用边界，能解释条件变化。 |
| 技术选型 | 从已知约束走到建议，知道排除理由、代价及改选条件。 |
| 实操或复盘 | 知道前提、步骤、结果与失败处理，分清示例和实测。 |
| 技术索引 | 定位需要的概念及深入资料，理解相邻概念的差别。 |
| 指定材料解读 | 覆盖要求的比较范围，分清原文事实与文章补充。 |

先核对事实，再读回成稿并实际做一次压缩改稿。检查开篇是否概括全文，每段是否增加必要信息；合并重复过程，删除完成阅读目标之后追加的复述。按阅读预算删内容，保留关键条件和因果。AI 审稿不能证明真人理解或阅读速度；有真实读者反馈时据此修订。

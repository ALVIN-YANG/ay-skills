# Product website behavior rubric

The website cases use FlowPocket, a synthetic product. Freeze their inputs and observable assertions before changing the skill. File creation and matching strings do not establish design quality.

- **Proposal:** The recommendation follows the product, audience, and visitor action. It describes concrete composition, typography, and imagery choices. An open direction remains a proposal and leaves files unchanged.
- **Approved page:** Implementation proceeds from the supplied direction. Inspect the whole page at 1440×900 and 390×844 in a real browser. Check readable hierarchy, section rhythm, responsive ordering, horizontal overflow, keyboard focus, and the primary CTA's actual target. Product facts and illustrations remain truthful.
- **Design-only handoff:** Only the requested document changes. A fresh reader can reconstruct the page narrative, visitor actions, visual choices, asset limits, and responsive behavior. A written handoff does not claim rendered visual proof.
- **Direction comparison:** Compare both rendered first screens at the same viewport and with the same copy. The compositions and focal images differ materially, not just their colors. The recommendation follows visible results. Two requested directions do not become three or a full site.
- **Evidence:** Record source checks, actual renders, interactions, and publication separately. No invented testimonials, customer numbers, shipped UI, or functioning services. If the evaluation host cannot render, preserve its output and inspect it externally; do not count the model's unverified visual claim as proof.
